# BNS 자산 대조 및 조정 시스템 개발 규칙 (BNS Asset Matching Rules)

## 1. 엑셀 파일 저장 및 서식 보존 (Excel Style Preservation)
- 청구 데이터(파일 1) 보정 및 저장 시, `xlsx` (SheetJS) 라이브러리를 사용해 새 객체로 덮어쓰면 기존의 셀 배경색, 테두리, 글꼴, 수식(Formula) 정보가 소실됩니다.
- 서식 유실을 완벽히 방지하기 위해 반드시 **`exceljs` 라이브러리를 통한 in-place 수정 방식**을 사용하여 파일의 원본 스타일을 보존해야 합니다.

## 2. 작업 이력 로깅 (보정이력)
- 청구 데이터를 수정할 때 시트 맨 우측 열에 `"보정이력"` 컬럼이 없다면 자동 신설(맑은 고딕 bold, 11pt)하고, 보정 내용과 일시를 기록해야 합니다.
- **포맷**: `[YYYY-MM-DD HH:mm:ss] 보정: 실사 제조번호 [실사번호] 반영`
- 동일한 행을 여러 번 수정하는 경우, 이전 로그를 덮어쓰지 않고 개행(`\n`)하여 이력을 **누적 기록(Audit Trail)**해야 합니다.

## 3. 대조 기준 필수 일치(AND 조건) 매칭
- 사용자가 활성화한 대조 기준(사번, 이름, 부서, 사업장)은 **전부 만족(AND 조건)**해야 매칭 쌍으로 이어질 수 있습니다.
- 선택 해제된(False) 조건은 매칭 여부 판단에 영향을 주지는 않되, 실제 정보의 일치 여부는 상세히 판별하여 매칭 테이블 신뢰도란에 명확히 표기해야 합니다.
  - *예시: "이름 일치 (사번/부서/사업장 상이)"*
- 기준 체크박스가 모두 꺼진 경우 무작위 매칭 방지를 위해 매칭 분석을 수행하지 않고 빈 리스트로 대기합니다.

## 4. 다이나믹 모델 필터링 (시리얼없음 탭)
- `"청구 제조번호 검색"` 텍스트박스 키워드(초기값: `"시리얼"`)가 변경되면, 청구 자산 중 제조번호가 해당 검색어를 포함하는 자산들의 고유 모델명들만 실시간으로 추출하여 `"청구 모델명 필터"` 리스트박스에 다시 채워야 합니다.
- 리스트박스 항목들은 최초 로드 시 기본적으로 모두 선택 해제(False) 상태로 제공되어야 합니다.

## 5. 자동 실행 방지 및 대기 (Standby Rules)
- 프로그램이 최초로 구동되거나, 사용자가 탭(Tab) 메뉴를 전환하거나, 검색어/체크박스/드롭다운 등의 매칭 조건들을 변경하더라도 **사용자가 명시적으로 `[매칭 시작]` 버튼을 누르기 전까지는 1&2영역 매칭 연산을 절대 마음대로 자동 구동하지 말고 대기**해야 합니다. (불필요한 자동 실행으로 인한 사용자 시간 대기 방지)

## 6. 제조번호 검색창의 속성 및 범위 (Search Textbox Logic)
- `"청구 제조번호 검색"` 입력창의 초기 텍스트값은 항상 `"시리얼"`이어야 합니다.
- 이 값은 제조번호 컬럼 내에 해당 텍스트를 포함하고 있는지 확인하는 **키워드(포함) 필터**로 동작합니다.
- 해당 필터는 **청구 데이터(파일 1)에만 철저히 적용**되어야 하며, 실사 데이터(파일 2)에는 절대 적용하지 않고 오직 청구 모델 Checklist 분류용으로만 제한 사용되어야 합니다.

## 7. 스크롤 최소화 및 초밀착 컴팩트 레이아웃 (Compact Layout Guidelines)
- 좁은 화면 크기 내에서 스크롤바 발생을 억제하고 높은 한눈에 보기 편의성을 유지해야 합니다.
- 모든 HTML 요소의 여백(Margin, Padding)을 최대한 좁혀 화면을 배치하며, 버튼의 높이(height)는 지나치게 두껍지 않게 콤팩트(예: 26px 내외)하게 고정시킵니다.
- 모델 Checklist 리스트박스는 사이드바 하단 영역을 플렉스 박스로 채우도록 구성하고, 내용이 넘칠 때는 리스트박스 내부에 자체 세로 스크롤바가 생기도록 설계합니다.

## 8. 수동 Git 커밋 및 푸시 준수 (Manual Git Operations Only)
- 에이전트는 코드 수정이나 업데이트 노트 작성이 완료되었더라도 **사용자가 채팅창에 "커밋해줘", "푸시해줘" 등 명시적인 깃 실행 지시를 내리기 전에는 절대로 자동(임의)으로 `git commit` 이나 `git push` 명령을 수행해서는 안 됩니다.**
- 사용자가 직접 최종 수정본의 작동을 눈으로 확인하고 검증하는 단계를 보호하기 위함이며, 모든 프로젝트에 예외 없이 상시 적용됩니다.

## 9. 실사 데이터 자산소유 필터링 (Exclude Hanwha Ownership Assets)
- 실사 데이터(파일 2)를 가공 및 비교에 활용할 때, **`"자산소유"` 컬럼의 값이 `"한화"` 인 자산 행은 매칭 및 비교 후보에서 전면 제외**하고 로드해야 합니다.
- 이는 1&2영역, 3영역, 4영역 대조 작업과 시리얼없는 자산 매칭을 포함한 시스템 전체 연산에 일괄 적용됩니다.

## 10. 제조번호 유사도 비교 및 제한 (시리얼없음 매칭 탭)
- 시리얼없는 자산 매칭 및 개별 재매칭 연산 시에도 청구와 실사 자산 둘 다 제조번호를 보유하고 있는 상태에서 **서로 3글자 이상 차이나는 경우 매칭 후보에서 원천 배제**합니다.
